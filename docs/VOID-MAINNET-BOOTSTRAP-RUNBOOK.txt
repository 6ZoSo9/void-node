VOID MAINNET BOOTSTRAP RUNBOOK (HIGH-LEVEL)

This file is a HUMAN RUNBOOK that ties together the mainnet bootstrap scripts.
It is NOT code. Do NOT try to execute it.

----------------------------------------------------------------------
0. KEY FILES / SCRIPTS
----------------------------------------------------------------------

Configs:
  - config/void-mainnet-bootstrap-dev.json
      * Dev/anvil bootstrap config (unsafe for mainnet).
  - config/void-mainnet-bootstrap-mainnet.template.json
      * Zero-address template for real mainnet.
      * Must be filled via template-fill before use.
  - config/void-mainnet-bootstrap-mainnet.live.json
      * Filled config for REAL mainnet (owners, validators, etc.).
      * Generated by ops/void-mainnet-bootstrap-template-fill.sh.

Core scripts:
  - ops/void-mainnet-dev-bootstrap-full.sh
      * Full dev bootstrap on anvil (chainId 2050).
      * Deploys UpdateGate/AdminGate/ConfigGate/ValidatorSet/VoidToken/
        VoidTreasury/OpsTreasury/RewardEngine.
      * Moves premine to VoidTreasury; funds Ops + validator; sanity checks.

  - ops/void-mainnet-bootstrap-plan.sh
      * READ-ONLY PLAN: prints what would be deployed/wired based on config +
        RPC, no transactions sent.

  - ops/void-mainnet-bootstrap-safety.sh
      * PLAN + Prometheus health checks for dev/mainnet-core.
      * Gatekeeper: refuses to pass if core pillars/metrics are unhealthy.

  - ops/void-mainnet-bootstrap-run.sh
      * DEV-ONLY RUN wrapper.
      * Requires:
          VOID_MAINNET_BOOTSTRAP_DEV=1
          RPC = http://127.0.0.1:8545
          chainId = 2050
      * Delegates to ops/void-mainnet-dev-bootstrap-full.sh and then re-runs
        PLAN + SAFETY on dev.

Mainnet config tooling:
  - ops/void-mainnet-bootstrap-mainnet-lint.sh
      * Offline lint for a mainnet config JSON.
      * Rejects:
          - zero addresses for roles,
          - known anvil/dev addresses,
          - obviously broken validator configs.
      * This is the "offline static sanity check".

  - ops/void-mainnet-bootstrap-mainnet-dryrun.sh
      * DRYRUN (NO TXS): runs MAINNET-LINT and then PLAN against a given RPC.
      * Confirms:
          - config looks sane,
          - RPC chainId == 2050 (VOID),
          - PLAN summary matches expectations.

  - ops/void-mainnet-bootstrap-template-fill.sh
      * Fills the mainnet.template.json into mainnet.live.json using environment:
          VOID_ADMIN_GATE_OWNER
          VOID_UPDATE_GATE_OWNER
          VOID_CONFIG_GATE_OWNER
          VOID_TREASURY_OWNER
          VOID_OPS_TREASURY_OWNER
          VOID_REWARD_ENGINE_OWNER
          VOID_VALIDATORSET_OWNER

          VOID_VALIDATOR_0_REWARD
          VOID_VALIDATOR_0_STAKE
          VOID_VALIDATOR_0_CONSKEY
      * Rejects:
          - zero addresses,
          - known anvil/dev addresses.
      * Intended for REAL mainnet when we have hardware-wallet / LUKS-backed
        keys ready.

----------------------------------------------------------------------
1. DEV / ANVIL REHEARSAL FLOW (SAFE)
----------------------------------------------------------------------

Goal: confirm contracts + tokenomics pipeline end-to-end on anvil (chainId 2050).

1) Ensure tests & node are healthy (outside this runbook):
     forge test
     ./ops/void-mainnet-health-all.sh
     ./ops/void-mainnet-pillars-health-all.sh

2) Run full dev bootstrap pipeline:
     ./ops/void-mainnet-dev-bootstrap-full.sh

   This will:
     - Deploy UpdateGate/AdminGate/ConfigGate/ValidatorSet/VoidToken/
       VoidTreasury/OpsTreasury/RewardEngine to anvil.
     - Move premine into VoidTreasury (dev).
     - Fund OpsTreasury + dev validator.
     - Run dev tokenomics invariants (supply == Treasury + Ops + Reward + validator).

3) Run PLAN against dev config:
     ./ops/void-mainnet-bootstrap-plan.sh \
       --config config/void-mainnet-bootstrap-dev.json \
       --rpc    http://127.0.0.1:8545

4) Run SAFETY:
     ./ops/void-mainnet-bootstrap-safety.sh \
       --config config/void-mainnet-bootstrap-dev.json \
       --rpc    http://127.0.0.1:8545 \
       --prom   http://127.0.0.1:9090

5) Optional DEV-ONLY RUN wrapper:
     VOID_MAINNET_BOOTSTRAP_DEV=1 \
     ./ops/void-mainnet-bootstrap-run.sh \
       --config config/void-mainnet-bootstrap-dev.json \
       --rpc    http://127.0.0.1:8545

   This is just a supervised wrapper around the dev bootstrap + PLAN + SAFETY.

3. REAL MAINNET PHASE (FUTURE – DO NOT IMPLEMENT YET)
----------------------------------------------------------------------

This section is intentionally high-level only. The real implementation will be
done LATER, when:

  - We have fresh, never-used mainnet keys for:
      * AdminGate master key / signer set
      * UpdateGate signer set
      * ConfigGate owner
      * VoidTreasury owner
      * OpsTreasury owner
      * RewardEngine owner
      * ValidatorSet owner
      * Initial validator(s) reward addresses

  - Those keys are:
      * Stored on LUKS-encrypted USB and/or hardware wallets.
      * NOT reused from dev/anvil.
      * Backed up carefully (seed, sharded where appropriate).

High-level steps (to be detailed later):

  1) Generate and record real mainnet addresses using hardware wallets and/or
     LUKS-encrypted key material. NEVER from anvil dev accounts.

  2) Export those addresses into environment variables:
       VOID_ADMIN_GATE_OWNER=...
       VOID_UPDATE_GATE_OWNER=...
       VOID_CONFIG_GATE_OWNER=...
       VOID_TREASURY_OWNER=...
       VOID_OPS_TREASURY_OWNER=...
       VOID_REWARD_ENGINE_OWNER=...
       VOID_VALIDATORSET_OWNER=...
       VOID_VALIDATOR_0_REWARD=...
       VOID_VALIDATOR_0_STAKE=...
       VOID_VALIDATOR_0_CONSKEY=...

  3) Run template-fill OFFLINE to produce:
       config/void-mainnet-bootstrap-mainnet.live.json

  4) Run MAINNET-LINT OFFLINE (no RPC):
       ./ops/void-mainnet-bootstrap-mainnet-lint.sh \
         --config config/void-mainnet-bootstrap-mainnet.live.json

     If this fails, STOP. Fix config/keys before proceeding.

  5) Run MAINNET-DRYRUN against a SAFE pre-mainnet RPC (e.g. genesis rehearsal):
       ./ops/void-mainnet-bootstrap-mainnet-dryrun.sh \
         --config config/void-mainnet-bootstrap-mainnet.live.json \
         --rpc    <safe-genesis-RPC>

     This still sends NO transactions. It only checks that config + chainId
     line up.

  6) REAL MAINNET RUN:
       - Will be a separate, heavily-gated script (NOT committed yet).
       - Must require:
           * confirmation of chainId,
           * hardware-wallet confirmation for each transaction,
           * Prometheus + pillars health gates,
           * explicit operator confirmation (Y/N) at each major step.

     This script will:
       - Deploy UpdateGate/AdminGate/ConfigGate/ValidatorSet/VoidToken/etc.
       - Move premine into VoidTreasury.
       - Fund OpsTreasury + initial validators.
       - Run on-chain tokenomics invariants.
       - Commit a bootstrap manifest hash to VOID chain + external backups.

  7) After mainnet live:
       - Lock core under UpdateGate/AdminGate policy.
       - Move day-to-day operations through OpsTreasury and controlled
         RewardEngine/validator flows.
       - Premine key is never used as a hot wallet; ideally burned/retired
         after bootstrap.
