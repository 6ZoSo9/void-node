# DataNet registry single-transaction broadcast authorization v1

Marker: `VOID_DATANET_REGISTRY_SINGLE_TRANSACTION_BROADCAST_AUTHORIZATION_V1`

Status: exact broadcast authorization artifact. No transaction is submitted by
this gate.

## Purpose

Convert one green
`VOID_DATANET_REGISTRY_BROADCAST_AUTHORIZATION_REQUEST_V1` into an exact,
short-lived authorization for one later broadcast attempt.

This gate is narrower than broadcasting:

- it rebuilds the signed-transaction verification and request lineage;
- it requires the exact transaction-bound confirmation generated by the request;
- it permits at most one submission attempt;
- it authorizes only the exact signed transaction hash;
- it binds the contract-creation consequence and bounded gas/fee spend;
- it forbids replacement transactions and automatic retries;
- it requires a fresh pre-broadcast observation; and
- it requires durable single-use consumption before broadcaster access.

## Exact confirmation

The required confirmation is:

```text
authorizeDatanetRegistryDeploymentBroadcastV1:<signed_transaction_id>:<signed_transaction_hash>:<candidate_id>:<transaction_fingerprint_sha256>
```

A generic instruction such as “continue”, “I authorize”, or an unbound prefix
does not satisfy this gate.

## Time boundary

The authorization compiler creates a maximum five-minute authorization window.

A later broadcaster must recheck expiry at runtime before it can access the
signed transaction bytes.

## Scope

The authorization records:

- exact single transaction only;
- exact signed transaction/hash only;
- one submission attempt only;
- single use;
- fresh pre-broadcast observation required;
- durable consumption before broadcaster access required;
- exact contract-creation consequence authorized;
- exact bounded gas/fee spend authorized;
- no additional value transfer;
- no replacement transaction; and
- no automatic retry.

## Authority boundary

This source gate may create an authorization artifact with
`broadcast_authorized=true` only after the exact confirmation is provided to
the compiler.

The compiler itself still performs no:

- signed-transaction byte access beyond the upstream request rebuild;
- broadcaster access;
- transaction submission;
- transaction broadcast;
- deployment;
- Chain-2050 write;
- validator mutation;
- token/funds movement; or
- automatic retry.

## Precision compiler

The Precision runner rebuilds the complete signed request lineage, validates the
signed-verification receipt, and requires the exact confirmation before writing
one mode-0600 authorization JSON artifact.

It performs no RPC send method, SSH, Docker, systemd, signer, wallet, or
broadcaster action.
